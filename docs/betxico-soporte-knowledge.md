# Base Operativa Inicial - Soporte Betxico

## Reglas generales

- No prometer abonos, retiros, bonos, desbloqueos, verificaciones ni cierres sin evidencia y validacion interna.
- Si faltan datos, pedir solo lo necesario para avanzar.
- Para mensajes al cliente, responder con texto breve, claro y listo para copiar.
- Para analisis interno, separar datos confirmados, datos faltantes y siguiente accion.
- No inventar saldos, estados de Jira, respuestas de proveedores, movimientos bancarios ni resultados de KYC.

## Deposito no reflejado

Datos minimos para revisar:

- Correo registrado.
- AUTH ID o ID de cliente.
- Monto exacto.
- Fecha y hora aproximada.
- Clave de rastreo.
- Captura bancaria o CEP de Banxico cuando aplique.

Respuesta base:

Necesito que me compartas por favor la captura de tu deposito donde se vea fecha, monto y clave de rastreo. Si puedes descargar el CEP de Banxico, tambien ayudara a validar el movimiento con mayor precision.

## Retiros

Antes de responder, validar si el cliente ya dio correo y si existe ticket o registro de seguimiento. No prometer tiempos exactos si no hay confirmacion interna.

Datos minimos:

- Correo registrado.
- AUTH ID.
- Monto de retiro.
- Metodo o banco si el cliente lo menciona.
- Captura del estatus si existe.

Respuesta base:

Compárteme por favor tu correo registrado para revisar el estatus de tu retiro. Si el sistema requiere alguna validacion adicional, te indicaremos exactamente que informacion falta para darle seguimiento.

## KYC y documentos

Datos comunes:

- INE por ambos lados.
- Selfie sosteniendo INE.
- Caratula o estado de cuenta cuando se valida metodo de retiro/deposito.
- Documentos completos, claros, sin edicion ni recortes.

No decir que la cuenta ya quedo verificada hasta que el area correspondiente lo confirme.

## Bonos y rollover

No prometer aplicacion de bono si no se valida elegibilidad. Explicar condiciones de forma simple.

Puntos clave:

- El bono puede depender del primer deposito, monto minimo o activacion en promociones.
- Si hay rollover pendiente, el saldo puede estar restringido.
- Si el cliente juega antes de activar ciertas promociones, puede perder elegibilidad.

## Juegos y proveedores

Datos minimos:

- Nombre exacto del juego.
- Fecha y hora aproximada.
- Captura del error o historial.
- Explicacion breve de lo ocurrido.

No confirmar ganancias pendientes sin validacion del proveedor o sistema interno.

## Cierre de sesiones

Datos minimos:

- Correo o ID.
- Juego donde ocurre el problema.
- Captura del error si existe.

Respuesta base:

Voy a reportar el cierre de sesiones para ese juego. Mientras se procesa, intenta cerrar ventanas externas, borrar cache/cookies, actualizar el navegador y volver a ingresar en unos minutos.

## Escalacion

Escalar cuando:

- Falta acreditacion con evidencia completa.
- Hay rechazo bancario o retiro retenido.
- Hay posible problema de proveedor.
- Hay inconsistencia de KYC.
- El cliente esta molesto y requiere seguimiento formal.

En escalaciones, crear o actualizar ticket en Jira y registrar evidencia disponible.
